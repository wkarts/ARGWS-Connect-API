# Correção de CI — run 92297357423

## Escopo

Correção aplicada sobre a linha canônica da Connect|API 1.0.21 com Zapo nativo e VoIP direto, sem a Platform descontinuada.

## Falha 1 — API TypeScript

O build `develop api` falhava em amd64 e arm64 em `whatsapp.baileys.service.ts`, dentro de `fetchAllGroups()`.

O retorno de `groupFetchAllParticipating()` chegava ao `Object.values()` como `unknown[]`, fazendo o TypeScript rejeitar o acesso a propriedades de `GroupMetadata` (`id`, `subject`, `participants`, `creation`, `owner`, etc.).

### Correção

- O resultado de `Object.values()` foi tipado explicitamente como `GroupMetadata[]`.
- A lista de resposta agora usa `Partial<GroupMetadata> & { pictureUrl?: string; size: number }`.
- `participants` é incorporado condicionalmente durante a criação do objeto, sem indexação dinâmica não tipada.
- Nenhuma regra funcional do Baileys foi alterada.

## Falha 2 — Manager Docker build

O build `develop manager` falhava em amd64 e arm64 com:

```text
failed to calculate checksum ... "/dist": not found
```

A causa era estrutural: `manager/.dockerignore` excluía `dist`, enquanto `manager/Dockerfile` executava `COPY dist/ ...`.

### Correção

O Manager agora usa Docker multi-stage:

1. estágio Node 22 (`argws-connect-node:22-bookworm-slim`);
2. copia o fonte do Manager (`src`, `public`, `scripts`, `index.html`);
3. executa `npm run check`, `npm run build` e `npm run smoke`;
4. copia o `/app/dist` recém-gerado para o estágio Nginx;
5. mantém o runtime-config em `/docker-entrypoint.d/40-manager-runtime-config.sh`.

Com isso o build deixa de depender de artefato gerado/commitado no repositório.
