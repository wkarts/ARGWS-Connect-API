# Connect|API v1.3.0 — transcrição em todos os deploys

## O que mudou

- As stacks production, canonical, homologation, CloudPanel, Dockge, Compose raiz e Fersoft develop/production incluem um worker de transcrição no profile `transcription`.
- A imagem estável `ghcr.io/wkarts/argws-connect-transcription-worker` passa a ser publicada junto com API, Manager e DOCs nas tags `1.3.0`, `1.3`, `1` e `latest`.
- Fersoft mantém os próprios projetos e serviços, com uma réplica de transcrição por stack. O ditado continua apenas no develop principal; o botão de microfone no Manager acompanha `DICTATION_ENABLED`.
- Os exemplos de ambiente habilitam transcrição e o Manager, fixam uma réplica, uma inferência simultânea por broker e tmpfs de 1 GiB. O limite de memória permanece 4 GiB por worker.
- Inclui a correção de inicialização da PR #216, que evitou o acesso a um job nulo durante a medição de memória antes do modelo carregar, e os ajustes de áudio e filas promovidos desde a v1.2.1.

## Atualização de instalações existentes

Preserve `.env`, segredos, banco, RabbitMQ, MinIO, `./models` e demais volumes. Copie o Compose novo e ajuste o `.env` existente; trocar apenas `env.example` não muda flags antigas:

```dotenv
COMPOSE_PROFILES=operations,transcription
SPEECH_ENABLED=true
TRANSCRIPTION_ENABLED=true
MANAGER_FEATURE_TRANSCRIPTION=true
DICTATION_ENABLED=false
SPEECH_TRANSCRIPTION_REPLICAS=1
SPEECH_GLOBAL_CONCURRENCY=1
SPEECH_WORKER_CONCURRENCY=1
TRANSCRIPTION_WORKER_TMPFS_SIZE=1g
```

Mantenha quaisquer outros profiles da stack em `COMPOSE_PROFILES` (Fersoft inclui `nats,kafka,mysql,traccar`). Defina `ARGWS_CONNECT_API_IMAGE` e `ARGWS_CONNECT_TRANSCRIPTION_WORKER_IMAGE` no mesmo canal: `:latest` para produção, `:develop` para develop/homologação e `:1.3.0` para canonical. No develop principal, mantenha `DICTATION_ENABLED=true` se o ditado já estiver ativo e houver memória suficiente.

```bash
docker compose --env-file .env -f compose.yaml pull
docker compose --env-file .env -f compose.yaml up -d --pull never --remove-orphans
docker compose --env-file .env -f compose.yaml ps -a
```

Use `docker-compose.yml` no CloudPanel. Não execute `down -v`. Confira `GET /v1/speech/health`, logs de `before_model`/`after_model`, reinícios, OOM e um job curto concluído. `--remove-orphans` retira o serviço antigo de ditado das stacks Fersoft.

## Orçamento de memória e limite da validação

Após o warm-up corrigido no develop, as amostras registraram aproximadamente 2,54 GiB de RSS na transcrição e 2,49 GiB no ditado. São valores de partida, sem carga sustentada ou pico comprovado. Cada stack mantém seu próprio modelo; a vaga `SPEECH_GLOBAL_CONCURRENCY=1` só é compartilhada por workers no mesmo broker/vhost/exchange. Em uma VPS com várias stacks, reserve memória para **todas** as réplicas residentes e os demais serviços, monitore o host e reduza perfis ativos se faltar margem. Não atribua os OOMs históricos da Fersoft a uma vítima sem os eventos e IDs contemporâneos.

Um modelo menor ou um motor como whisper.cpp pode reduzir RAM, mas exige provisionamento seguro do modelo, integração com o contrato de jobs e comparação de precisão em português antes de substituir o motor atual. A troca de motor não faz parte desta release.
